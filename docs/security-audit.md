# Проверка безопасности — 5 ноября 2026

Проверены схема базы, реальные Supabase Auth/REST/RPC, исходники, достижимая история Git и браузерная production-сборка. Итоговая схема содержится в единственной миграции `202611050001_initial.sql`. После объединения миграция повторно проверена на пустом PostgreSQL.

Облачный API проверялся с публичным ключом без входа, под постановщиком и двумя исполнителями. Использованы временные объекты и задачи; после проверки они удалены, события проверки сохранены. Существующие клиентские задачи не изменялись.

| Требование                    | Результат                                                                                                                                                                                                                                                       |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Ограничения на уровне базы | RLS включён на всех четырёх таблицах. Прямые SQL- и REST-запросы отклоняют недопустимые действия. Анонимное чтение запрещено.                                                                                                                                   |
| 2. Изоляция исполнителей      | Исполнитель видит только свои задачи и связанные объекты. Чтение, изменение, переназначение и удаление чужой задачи не выполняются. Создание задач, редактирование объектов и повышение роли запрещены.                                                         |
| 3. Переходы статусов          | Прямое изменение `status` запрещено. RPC и триггер проверяют пользователя, переход и комментарий. Проверены 75 комбинаций ролей и статусов, полный цикл с доработкой и параллельные запросы. Устаревшее действие возвращает HTTP 409 без повторного выполнения. |
| 4. Неизменяемость истории     | Пользовательскому API запрещены INSERT, UPDATE и DELETE событий. Автор и время задаются базой. После удаления задачи или объекта история с исходным ID задачи остаётся доступна постановщикам через API; отдельный экран архива не реализован.                  |
| 5. Запрет регистрации         | В облачном `/auth/v1/settings` подтверждено `disable_signup: true`. Прямой signup отклонён с `signup_disabled`.                                                                                                                                                 |
| 6. Секретные ключи            | Серверные ключи отсутствуют в проверенных исходниках, достижимой истории Git и браузерной сборке. `.env`-файлы не закоммичены. Фронтенд использует публичный ключ.                                                                                              |

## Повторяемые проверки

- `npm run test:db`: 20 групп проверок, включая 75 комбинаций ролей и статусов, параллельные запросы и сохранность истории после удаления. Нужен `TEST_DATABASE_URL` отдельного временного PostgreSQL, как описано в README.
- `npm run audit:cloud -- --probe`: 13 групп проверок реального Supabase на временных записях. Нужны ключи и пароли трёх тестовых аккаунтов из `.env`. Без `--probe` выполняются только чтение настроек Auth и анонимные запросы. Отчёт сохраняется в игнорируемом `.local/security-cloud.json`, без ключей, паролей и токенов.
- `npm run audit:secrets`: проверяет отслеживаемые файлы, достижимую историю Git и готовый `dist`. Перед проверкой новой сборки выполнить `npm run build`.
- Сборка TypeScript/Vite, 3 теста доступных действий и 2 браузерных сценария также проходят.

Права пользователей проверялись с публичным ключом и собственными сессиями. Сервисный ключ использовался только локально для административного контрольного чтения и не относится к пользовательскому API приложения.
